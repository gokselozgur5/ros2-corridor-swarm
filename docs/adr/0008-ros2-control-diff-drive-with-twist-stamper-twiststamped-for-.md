# ADR-0008: ros2_control diff_drive with twist_stamper (TwistStamped) for the Gazebo vehicle

Status: Accepted (date: 2026-10-24, commits b3f1d55 .. 1b5048c/5d65cf7, all 2026-10-24; Phase 1 #5 proven per PLAN.md:9)

## Context
Gazebo Harmonic owns physics, motors and sensors; nothing in ROS fakes a sensor (ARCHITECTURE.md:41). The UGV is a 4-wheel differential chassis (ugv.urdf.xacro:3), wheel radius 0.20 m, wheel_y 0.40 m so track 0.80 m (ugv.urdf.xacro:15-19; controllers_v1.yaml:15-16); ARCHITECTURE.md:90,92 calls it a skid steer. The vehicle contract is `/vN/cmd_vel` in, `/vN/odom` out, shared by `unicycle_sim`, the gz `OdometryPublisher` and `diff_drive` backends (ARCHITECTURE.md:23,98). The jazzy `diff_drive_controller` takes only `TwistStamped` and has no `use_stamped_vel` parameter (twist_stamper.py:3; commits f0d5c91 added `use_stamped_vel: false`, 63f3696 removed it). ROS 2 Jazzy is a source build with no ros2_control (CLAUDE.md:8), so the control stack is cloned via `ws/deps.repos` (ros2_control, ros2_controllers, gz_ros2_control, branch jazzy: deps.repos:106-117) and trimmed by `steps/09_ros2_control_build.sh`.

## Decision
- `ugv.urdf.xacro:94-109`: behind `use_ros2_control`, a `<ros2_control type="system">` block with `gz_ros2_control/GazeboSimSystem`, four wheel joints (front/rear left/right) each with a `velocity` command interface (min -30, max 30) and `position`/`velocity` state interfaces.
- `ugv.gazebo.xacro:65-72`: `gz_ros2_control::GazeboSimROS2ControlPlugin` loads `$(arg controllers_yaml)` under namespace `/${ns}`; `unless use_ros2_control` the gz `OdometryPublisher` runs instead (:73-83). The gz `JointStatePublisher` on `${ns}/joint_states` runs in both cases (:84-88).
- `corridor_gz/config/controllers_v1.yaml`: `/v1/controller_manager` at `update_rate: 100`, `use_sim_time: true`, controllers `joint_state_broadcaster` and `diff_drive` (`diff_drive_controller/DiffDriveController`); `/v1/diff_drive`: two `v1/*_wheel_joint` names per side, `wheels_per_side: 2`, `wheel_separation: 0.80`, `wheel_radius: 0.20`, `odom_frame_id: v1/odom`, `base_frame_id: v1/base_footprint`, `enable_odom_tf: true`, `publish_rate: 50.0`, `cmd_vel_timeout: 0.5`, linear.x max/min 4.0/-2.0 m/s, max_acceleration 2.0; angular.z max/min 2.0/-2.0 rad/s, max_acceleration 3.0 (lines 1-28).
- `corridor_gz/launch/sim.launch.py:22-25,43-49`: the xacro gets `controllers_yaml:=.../controllers_v1.yaml`; when `use_ros2_control`, two `controller_manager/spawner` nodes on `/v1/controller_manager` (`--controller-manager-timeout 60`); the diff_drive spawner passes `--controller-ros-args '-r /v1/diff_drive/odom:=/v1/odom'`; a `corridor_nav twist_stamper` node, namespace `v1`, `frame_id: v1/base_footprint`, `use_sim_time: true`, same condition.
- `corridor_nav/corridor_nav/twist_stamper.py`: subscribes `cmd_vel` (Twist), publishes `TwistStamped` on `out_topic` (default `diff_drive/cmd_vel`) with the node clock stamp and the `frame_id` param (default `base_footprint`) (lines 13-23). Entry point `twist_stamper` (setup.py:29).
- `steps/09_ros2_control_build.sh`: `vcs import` from `ws/deps.repos` (:8); apt `python3-typeguard python3-jinja2` for generate_parameter_library (:9); COLCON_IGNORE on every `ros2_controllers/*` package except `diff_drive_controller`, `joint_state_broadcaster`, `ros2_controllers`, `ros2_controllers_test_nodes` (:11-13); prunes `diagnostics`, `gz_ros2_control_demos`, `rqt_controller_manager`, `ros2_control` metapackage (:14-18); builds `tl_expected`/`tl-expected` first because rsl declares the apt key `libexpected-dev`, not the package (:20-21); then `--packages-up-to gz_ros2_control diff_drive_controller joint_state_broadcaster` with `-DBUILD_TESTING=OFF` (:23-24).

## Alternatives considered
- Keep publishing Twist and set `use_stamped_vel: false` on the controller: tried (f0d5c91), reverted (63f3696, "jazzy diff_drive has no such parameter").
- Make the follower and planner tools publish TwistStamped: rejected so the kinematic and Gazebo backends keep one `cmd_vel` contract (twist_stamper.py:3-4; ARCHITECTURE.md:98).
- gz `DiffDrive` system plugin instead of ros2_control: not mentioned anywhere in the repo. ARCHITECTURE.md:43 states the reason for ros2_control: motors have inertia, slip and limits.

## Consequences
- Good: `cmd_vel` drives real wheel joints through the controller's velocity and acceleration limits (controllers_v1.yaml:23-28); `#5` proof: `cmd_vel` 1.0 m/s for 5 s moves odom x by 3.5-6.5 m and `/v1/joint_states` reports wheel velocity (steps/08_proofs.sh:101-115). Follower, planner tools and `unicycle_sim` are unchanged (twist_stamper.py:3-4).
- Good: only `diff_drive_controller` and `joint_state_broadcaster` are built from ros2_controllers (steps/09:11-13); still 42 control packages on the underlay (ARCHITECTURE.md:102).
- Bad: one extra hop and node per vehicle (`cmd_vel` -> `twist_stamper` -> `diff_drive/cmd_vel`); the stamp is the stamper's clock, not the publisher's (twist_stamper.py:20).
- Bad: a third odometry owner (`diff_drive`, next to `unicycle_sim` and gz `OdometryPublisher`), switched by xacro if/unless and launch conditions; the launch split is still to do (ARCHITECTURE.md:98). Wheel odometry is not used for navigation: on the skid steer its yaw read 119 deg while the IMU read 7 deg after slipping against a crate, so the follower positions by fix and heads by IMU (#19, ARCHITECTURE.md:90, PLAN.md:11).
- Bad: `controllers_v1.yaml` hardcodes the `v1` namespace, joint names and frames (lines 1,10,13-19); nothing in the repo parameterises it for another vehicle.
